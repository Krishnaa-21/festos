# API Specification: `approvals`

> Owner: `P3`  
> Base Path: `/api/v1/approvals`  
> Status: `IMPLEMENTED`

---

## 1. Overview
The Approvals framework intercepts high-risk mutations generated by ChangeService or manual elevated requests. Operations requiring sign-off remain in status `PENDING_APPROVAL` until an authorized approver (e.g., Festival Director or Finance Manager according to policy) accepts or rejects the request. Approving an approval request automatically executes the underlying stored `ChangeSet` mutation inside a transactional savepoint and appends an immutable audit record.

---

## 2. Endpoints

### 2.1 `GET /api/v1/approvals`
- **Description**: List approval requests with pagination and status/role filters.
- **Headers**:
  - `Authorization: Bearer <jwt>`
- **Query Parameters**:
  - `page` (int, default: 1)
  - `page_size` (int, default: 20)
  - `status` (string, optional: `PENDING`, `APPROVED`, `REJECTED`)
  - `entity_type` (string, optional)
  - `required_role` (string, optional)
- **Response `200 OK`**:
```json
{
  "data": {
    "items": [
      {
        "id": "app_5a6b7c8d",
        "change_set_id": "cs_1234567890ab",
        "entity_type": "room_allocation",
        "entity_id": "plan_candidate_c",
        "status": "PENDING",
        "required_role": "FESTIVAL_DIRECTOR",
        "requested_by": "usr_acc_01",
        "reason": "Relaxing gender separation constraint for Contingent 12 due to hostel wing outage",
        "created_at": "2026-10-30T13:00:00Z",
        "approved_by": null,
        "approved_at": null,
        "rejection_reason": null
      }
    ],
    "total": 1,
    "page": 1,
    "page_size": 20,
    "total_pages": 1
  },
  "meta": {},
  "warnings": []
}
```

### 2.2 `GET /api/v1/approvals/{id}`
- **Description**: Get full details of an approval item, including stored payload and reason.
- **Headers**:
  - `Authorization: Bearer <jwt>`
- **Response `200 OK`**:
```json
{
  "data": {
    "id": "app_5a6b7c8d",
    "change_set_id": "cs_1234567890ab",
    "entity_type": "room_allocation",
    "entity_id": "plan_candidate_c",
    "status": "PENDING",
    "required_role": "FESTIVAL_DIRECTOR",
    "requested_by": "usr_acc_01",
    "reason": "Relaxing gender separation constraint for Contingent 12 due to hostel wing outage",
    "payload": {
      "plan_id": "plan_candidate_c",
      "overridden_constraint": "GENDER_SEPARATION"
    },
    "created_at": "2026-10-30T13:00:00Z"
  },
  "meta": {},
  "warnings": []
}
```

---

### 2.3 `POST /api/v1/approvals/{id}/approve`
- **Description**: Approve a pending item. Executes the stored `ChangeSet` mutation and updates status to `APPROVED`.
- **Headers**:
  - `Authorization: Bearer <jwt>`
- **Request Body**:
```json
{
  "reason": "Director sign-off granted following contingent head verbal confirmation"
}
```
- **Response `200 OK`**:
```json
{
  "data": {
    "approval_id": "app_5a6b7c8d",
    "change_set_id": "cs_1234567890ab",
    "status": "APPROVED",
    "approved_by": "usr_dir_01",
    "approved_at": "2026-10-30T13:25:00Z",
    "execution_result": {
      "status": "APPLIED",
      "change_set_id": "cs_1234567890ab",
      "violations": [],
      "audit_event_ids": ["aud_77a88b99c"]
    }
  },
  "meta": {},
  "warnings": []
}
```

---

### 2.4 `POST /api/v1/approvals/{id}/reject`
- **Description**: Reject a pending approval item with a mandatory rejection explanation.
- **Headers**:
  - `Authorization: Bearer <jwt>`
- **Request Body**:
```json
{
  "reason": "Cannot relax safety constraint; reroute to External Property Beta instead"
}
```
- **Response `200 OK`**:
```json
{
  "data": {
    "approval_id": "app_5a6b7c8d",
    "status": "REJECTED",
    "rejection_reason": "Cannot relax safety constraint; reroute to External Property Beta instead",
    "rejected_by": "usr_dir_01",
    "rejected_at": "2026-10-30T13:26:00Z"
  },
  "meta": {},
  "warnings": []
}
```

---

### 2.5 `GET /api/v1/approvals/policies`

  - `Authorization: Bearer <jwt>`
